# Streaming Inference and Context Compression for Long-Context LLMs

Long-context systems do not all solve the same problem. Some methods extend the model's usable context length during training or fine-tuning; others make inference over very long inputs affordable; others compress prompts so the model can focus on the most relevant content. StreamingLLM, LongLoRA, and LLMLingua are useful to compare because they each attack a different bottleneck in long-context deployment.

StreamingLLM ("Efficient Streaming Language Models with Attention Sinks", Xiao et al., 2023, arXiv:2309.17453) targets inference over effectively unbounded streams. The paper identifies "attention sinks": a small number of initial tokens attract substantial attention even when they are not semantically meaningful. Instead of recomputing attention over the entire history or truncating aggressively, StreamingLLM keeps a rolling cache of recent tokens plus a small set of initial sink tokens. The result is a training-free method that stabilizes generation far beyond the nominal training window. The authors report stable language modeling with Llama-2, MPT, Falcon, and Pythia over inputs up to 4 million tokens and more. In streaming settings, they report up to 22.2x speedup over a sliding-window recomputation baseline. For agent systems, this matters when dialogue or logs become effectively endless: the method makes persistent interaction feasible without paying quadratic attention cost over the whole transcript.

LongLoRA ("LongLoRA: Efficient Fine-tuning of Long-Context Large Language Models", Chen et al., 2023, arXiv:2309.12307) addresses a different problem: how to extend a pretrained model's context window without full-cost long-context training. The paper introduces shifted sparse attention (S^2-Attn) for efficient training and an improved LoRA setup that also trains embeddings and normalization layers. The authors emphasize the quadratic cost issue directly: training with context length 8192 requires roughly 16x the self-attention compute of 2048. LongLoRA uses sparse local attention in training while preserving standard dense attention at inference. The reported system-level result is strong: Llama 2 7B is extended from 4k to 100k context, and Llama 2 70B to 32k, on a single 8x A100 machine. A comparison table reproduced in later LongQLoRA documentation gives concrete perplexity numbers for LongLoRA at 8k evaluation context: LongLoRA-LoRA-7B-8K reaches 8.20 perplexity on PG19 and 2.78 on Proof-pile, while LongLoRA-Full-7B-8K reaches 7.93 on PG19 and 2.73 on Proof-pile. Those numbers are close to MPT-7B-8K (7.98 and 2.67), which suggests the extension retains reasonably competitive long-context language modeling quality.

LLMLingua ("LLMLingua: Compressing Prompts for Accelerated Inference of Large Language Models", Jiang et al., 2023, arXiv:2310.05736) is not a context-extension method in the architectural sense. It is a prompt compression method. The key idea is to use a smaller model's perplexity estimates to decide which parts of a prompt are redundant and can be compressed more aggressively. That makes it particularly useful for RAG and agent pipelines, where the issue is often not model context size alone but inefficient use of retrieved tokens. The reported compression numbers are concrete and practical. On GSM8K, full-shot prompting used 2,366 tokens and achieved 78.85 EM. LLMLingua compressed that to 117 tokens, a 20x compression ratio, while retaining 77.33 EM, only 1.5 points lower. On BBH, it used 110 tokens at 56.85 EM, compared with 774 tokens and 70.07 EM for the full-shot baseline. The project page also reports end-to-end latency improvements from 8.6 seconds without compression to 4.9 seconds at 2x compression, 2.3 seconds at 5x, and 1.3 seconds at 10x, corresponding to practical speedups of 1.7x to 5.7x. LongLLMLingua, the long-context extension of the method, reports up to a 21.4% improvement on NaturalQuestions multi-document QA while using around 4x fewer tokens.

For agent design, these methods can be combined rather than treated as competitors. StreamingLLM is best understood as an inference-time memory/cache strategy for effectively infinite streams. LongLoRA is a fine-tuning strategy for teaching the base model to tolerate much longer contexts. LLMLingua is a prompt-budget optimization strategy that helps pack more relevant evidence into the available window. If the agent must maintain long conversations, StreamingLLM-style KV retention is attractive. If the base model must reason over 32k to 100k token contexts, LongLoRA-style fine-tuning is relevant. If the main bottleneck is that RAG or tool traces produce too many tokens, LLMLingua-style compression may yield a bigger win than raw context expansion.
